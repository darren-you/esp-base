# C3 空产品状态查询的空指针故障

2026-10-02，正式 USB 控制台与完整产品授权的 C3 测试签名固件在空产品状态查询时触发 panic。本文记录实际故障与修正；测试签名和实板实验均不等于生产发布。

## 触发与定位

原输入为 Base `9564d74f7bd7dfa64334680e1c07a8eca2abc9ef`，运行固件集合与公开 `61b4adc3bc7ce05424972f69cfd8e945fce50fd8` 相同。固定 SDK 为 `578cf89c343e388db43ba1f4ddcd602fedcb763c`，lwIP 为 `2758df4cd3666b3b2a5b53830148379326425c0d`。C3 app 为 1183744 B，官方 RSA v2 验签通过，SHA-256 为 `77d15d4bbb510663c1bdac88f6ccf581898c8b6101289aa5628d03a23bfec1bf`。

按维护者丢弃 ESP 数据的授权，擦除唯一连接 C3 的完整 Flash，写入正式分区、原始启动入口与空白数据区，并逐字节读回。Base 达到 READY／EMPTY，公开 `status` 返回配置版本 0；随后未修改的 `device_control.py` 发送 `product.status`，设备 panic 并重启。客户端原有 5 秒期限结束，不是设备正常查询耗时超过期限；这次实验尚未提交 Wi-Fi 配置。

精确 ELF 将故障返回地址 `0x4203066e` 定位到 `esp_base_protocol.c:551` 的响应容量计算。实际栈中 `active.present` 为 0，`active.product_id` 为 NULL。该镜像的反汇编先从 `SP+492` 加载产品 ID 并调用 ROM `strlen`，之后才从 `SP+488` 加载 present 标志，用乘法裁决容量增量。因此本次空产品分支实际执行了 `strlen(NULL)`。这里只记录这份固定构建的机器行为，没有据此认定上游编译器故障。

## 修正

Base 内部活动产品快照新增 `product_id_size_bytes`。存在活动产品时，长度来自既有、不可变的授权产品 ID；空产品视图保留全零长度。协议层用两个显式长度计算响应容量，不再对可空产品 ID 调用 `strlen`。正式头文件、协议测试替身与真实签名生命周期断言共同更新。

公开产品状态仍是原十字段合同，未新增 wire 字段；公开 CLI、查询的单次 5 秒期限、SDK 配置和四份依赖锁保持不变。修正没有建立旧字段别名，也没有修改产品安装、停止或升级语义。

## 软件验证

独立源码提交为 `94323b19ca72a5c33fac10a2efc7d8e77f3f4049`，归档 SHA-256 为 `fb2f1e979d0c2968e8e34a9952aab596d39298137056a5ca4c3369dcdbd6b70e`。两目标完整 host 与真实 RSA 签名 guest 生命周期通过；后者各运行 100 次安装／卸载及重开，并覆盖五个取消／停止失败场景。测试使用真实 Container／WAMR／wasi-sdk，Base 测试启用 ASan／UBSan。

固定 SDK 的完整双目标签名重建、官方验签和槽容量门均通过，四份依赖锁逐字节未变。首次重建的 GitHub TLS 连接故障单独保留；正常重试通过，没有修改代理、TLS 校验、SDK 或组件摘要。

## 实板复验记录

修正镜像的首次实板复验已经取得空产品 `product.status` 成功结果和精确 app 摘要，随后公开 `config.set` 成功提交 Wi-Fi 配置并实际联网。公开 `restart` 返回 running 后，新的 boot 保留同一设备身份与配置版本 1，并重新连上 Wi-Fi。

紧接着的产品查询返回 `unknown/operation_busy`，实验调用方要求立即 succeeded 的断言失败，因此该轮完整结果仍记为失败。原始日志确认不是 UUID 或配置丢失，也没有再次 panic。后续只读复验仅在设备明确返回 `operation_busy` 时重新查询，每次查询仍使用原始 CLI 的 5 秒期限；其他 unknown 立即失败，写命令不重发。

同一修正镜像的最终复验通过：首启空产品查询一次成功，公开配置命令一次成功提交版本 0→1，公开重启后设备身份保持不变、boot 身份改变、版本仍为 1，实际 Wi-Fi 在新 boot 的 uptime 2844 ms 时已连接。重启后的产品查询先两次返回忙，第三次成功；首启与重启后的产品十字段结果完全相同，无包、无活动产品、Container sequence 1，运行固件摘要均为上述修正 app。原始 CLI 逐字节未修改，固件未注入测试调用方。

完整 4 MiB Flash SHA-256 为 `64047df7ad3e4ec44590ed016bb2b1a1a5f16be619b247c5af35cd04ce6d491a`，写后完整读回相同。最终仓外实验调用方摘要为 `93959c76bfd1603d3c807ded1948792f4341f95f82cc9983273dd17627f0d7e6`；USB 查询／配置与重启 UART 日志摘要分别为 `dd9e85f1bfb03bc0db0a644ee8235a895221276b4b17b3f7cb8b5e9061688d17`、`0d440cf094af1259f741ae8079995faa04fb6459dd3f6fde4339ade75d94233d`。31 份输入、失败轮索引、最终原始日志及软件回归文件已冻结为仓外私有证据索引，摘要 `5d5e86f9163cfc53657e0bd6fc09dfbf1f81a098359027fc52dc11788375fffa`。初始 panic 和首轮重启查询忙的失败记录均保留。

每次实验结束均清空实验数据，恢复原 bootloader、分区表和完整 factory 槽，逐字节读回三份代码相同；原 MQTT 实验应用确认 Wi-Fi 关闭，串口释放，没有 eFuse 写入。旧身份、配置与实验 NVS 都已丢弃，不宣称恢复旧数据。原始 UART 与身份信息仅保存在仓外私有证据中。

ESP32 没有接线，本次仅取得其软件构建结果。此修正与 [C3 原生停止百轮切片](../operations/async-cancel-checkpoint.md)分别记录：百轮切片使用修正前的生产运行代码与仓外原生调用方，不证明此新镜像的公开管理或联网组合验收。
