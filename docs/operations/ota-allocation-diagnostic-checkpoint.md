# ESP 原生业务、MQTT 分块 OTA 与双目标容量验证

本文维护稳定技术合同与固定验证方法。动态计划、范围决议、当前结论和原始证据统一维护在 [ESP 统一交付 #35](https://github.com/darren-you/darren-space/issues/35)，不在本文复制待办或测试进度。R1—R7 编号保留，历史证据仍按原组合解释。

目标为低资源设备的 **MQTT 控制＋MQTT 分块数据＋现有签名 A/B OTA**。源码、软件验证、服务部署与实板安装分别核验；缓存和历史制品不构成干净冷构建证明。

## 目标职责与数据路径

| 所属对象 | 目标职责 |
| --- | --- |
| Base | 持久 UUID、配置、Wi-Fi／时间、唯一控制 owner、原生业务、升级协调与原 ID 结果 |
| MQTT | 复用既有严格 TLS 连接，承载认证控制、业务、固件块、应用层确认及结果；有界队列／outbox和重连 |
| OTA | 顺序写备用槽，完整摘要／签名／芯片／项目／尺寸验证，A/B、rollback 与启动确认 |
| Mac App | 本机 USB、身份核对与租约、设备协议，以及 Rust 核心／Swift 绑定的刷写和恢复 |
| Server／Web | 项目会话与设备授权、签名制品登记、MQTT 控制／分块发送、原 ID 账本和独立结果核对 |

公网路径为 Web／Server→既有 Broker→设备 MQTT→有界 OTA 来源→备用 app→完整验证／选槽→新 boot 本地确认→原 operation_id 持久结果。所有固件字节必须经过 MQTT；直连 HTTPS、LAN、USB 或维护脚本不能代替正式公网路径资格。Mac 数据连接移除后也须成立。无需新增设备入站公网端口、隧道或文件中转服务。

本机路线为 Mac App→本机协议／Rust薄绑定→实际 USB。保留 USB 下发 URL、设备 HTTPS 拉取的现有能力；直接刷写、首次分区装配和恢复独立验收，不把 URL 命令称为全 USB 数据传输。公网与本机入口共用唯一升级 owner 和持久收据。unknown 只查原 ID，不自动另起操作、更换目标或通道。

## 有界分块与恢复合同

- 控制开始只登记一次原操作与精确固件身份。二进制数据块采用独立操作内偏移／序号，不逐块消耗普通写命令的 32 槽守卫。绑定设备、boot、operation、偏移、长度和协议方向，保留认证与重放防护；严格拒绝 retained、错身份、冲突重复、越界和未授权数据。
- 优先使用设备按需请求、一个块在途的最小机制；块大小、认证头、缓冲所有权、队列／outbox、重试次数和各阶段绝对期限在实现中明确冻结。现有入站 4,096 B 上限计入全部封装；先按 1–2 KiB 数据块评估，最终以真实 RTT／吞吐和资源结果确定。
- 块仅在有限缓冲内交接，顺序写入准确 inactive 槽；不在 RAM 拼完整镜像，不增加 Flash 中转副本。MQTT 回调借用数据不能跨 poll 存活，控制 owner 不等待网络或长时间 Flash 操作。实际写入后才推进应用 ACK；PUBACK 不等于写入。相同块重传不能重复推进，丢失 ACK、乱序及迟到必须有确定结果。
- 同 boot 断连后的有限重传与真正断电续传分开定义。现有 V4 无持久分块偏移，首版可沿用安全失败／清理与原结果查询，不要求新增断电续传；不得把重连成功当作断电续传，也不为每块写 NVS。新操作只能在旧终态已证实后受理。
- 仍先持久化意图并逐字节读回，再允许 app 擦写。完整 signed bin 的摘要、签名、目标、尺寸及槽状态全部验证通过后才选槽。30 秒本地控制进展确认独立于 Broker 在线状态；成功需同槽 VALID、精确签名身份和成功收据提交读回。失败清理不能证明时保持 unknown。

具体 wire 格式见[设备协议](../design/device-protocol.md)，通用流式写入和持久结果见[OTA 恢复机制](../../firmware/components/ota_operation/README.md)。软件接线不能代替真实链路验收。

## 持久状态、分区与退役边界

保留 182 B V4 收据、来源／候选精确签名身份、pending／VALID、rollback、失败清理及原 ID 查询。旧 V3、损坏或未决记录必须阻断；不能清空 NVS 把未知状态当缺失。旧配置中退役扩展字段的受限读取／迁移须明确处理，保留真实 UUID、revision、Wi-Fi／MQTT、凭据和历史收据，不重置设备身份。

C3／ESP32 均为 4 MiB，双 app 各 `0x1e0000`。既有闲置数据区地址、C3／ESP32 的 `base_store` 和 ESP32 只读旧 AT 原字节区先保留；停止旧运行访问不意味着可立即重用旧区。应用 OTA 不改 bootloader 或分区表，布局更改另按[首次有线迁入合同](../../firmware/components/ota_operation/README.md#首次有线布局迁入)验收。

运行依赖清理须覆盖组件清单、双锁、构建、owner、配置、容量观察器、Server/Web 路由及界面。源码、配置发布与实体安装分别核验。共享基础设施只删除本产品的专属绑定，保留其他消费者的有效身份与运行能力。

## 容量预算与验收口径

| 项目 | C3／ESP32 合同 |
| --- | --- |
| 内部堆 | INTERNAL\|8BIT 历史最低值至少 16,384 B |
| 连续空间 | 内部最大连续块至少 24,576 B，并满足真实能力域下一最大合法申请 |
| 任务栈 | 每个真实任务最低余量至少 1,024 B，覆盖网络、OTA、控制、业务与 SDK 任务 |
| TLS／Wi-Fi | 证书、主机名和可信时间不降；IN 16,384／OUT 4,096 B、原生固定 TLS 缓冲、12 sockets；静态 RX／BA 各 6、动态 RX／TX 各 32。配置变更须有独立理由和复验，不能靠停网过门 |
| MQTT | 现有 3.1.1／严格 TLS，入站 4,096 B、发布 5,120 B、outbox 16,384 B 及原队列／在途预算；新增块与 ACK 的全部占用计入 |
| 原生业务 | 消息计数、二进制输入、暂停／恢复、100 ms 窗口和重启初始化；最大合法输入与真实背压 |
| OTA | 最大合法签名镜像，接收／写入／验签／NVS／回滚阶段与网络业务同存 |

历史最低堆、当前空闲、最大连续块、region minimum 与任务高水位分别报告，观察成本不加回，不拼接异时数据制造瞬时峰值。按[正式容量统计](../../tools/README.md#正式容量统计)使用真实分配器与任务实例记录；动态／延迟 region 的未覆盖前缀不推定有效，缺失日志尾段不算覆盖。统计生产者与解析器须随运行依赖改变同步，不删除失败原件或削弱门限。

复用已有 MQTT 连接可能减少资源，但不预先承诺内存和功耗收益。评价功耗收益时分别测量稳定待机及一次完整升级的电流／耗电、耗时、吞吐、CPU／时序与重连成本，保留供电方式、无线条件和候选身份；无功耗仪器时明确未测，不用堆数据替代功耗。

## 固定验收方法

### R1 原生业务与运行依赖

原生消息计数、二进制输入、暂停／恢复、非延期 100 ms 窗口和重启初始化由唯一控制 owner 消费。保持动态引擎、包槽、产品账本及联合包升级退役。新架构必须清除已退役组件、任务、监听与工具消费者；仓库、源码、配置和线上分别验收。

### R2 固件独立 OTA 与恢复

保留签名、目标几何、摘要、A/B、30 秒本地确认、唯一 operation、V4 写前读回及 unknown 语义。接入有界 MQTT 来源，保留本机 URL 来源及跨入口互斥。软件覆盖 A、写入中断、待选 C、pending C、VALID C、回滚 A、取消、存储损坏、旧格式与未决阻断；来源等待期间不持有短 Flash I/O claim。

### R3 固件生产者与真实消费者

Server／Web 完成设备授权、签名制品登记、MQTT 分块调度、应用 ACK、进度和原 ID 查询；取得完整真实固件字节经过正式 MQTT 路径的证明。真实 App 继续用已冻结 Rust／Swift 经 USB 完成信息、配置、控制、URL OTA、刷写与恢复；不依赖宿主远程服务，保留当前 App 的租约、未决记录及恢复原件。SDK 全矩阵独立验收，不能由产品子集扩大资格。

软件与真实客户端分别覆盖错误认证、错设备／boot／operation、重复／冲突／乱序块、ACK 丢失、Broker 重启、断连重连、取消、迟到、超长／截断、错摘要／签名／目标、过载、Flash／NVS 失败与结果丢失。第二操作和跨 USB 冲突必须拒绝；不自动重发未知写意图。

### R4 双目标分区与可复现构建

保留双目标既有分区与受控首次迁入。完成当前依赖的准确清单、双锁、独立 build／sdkconfig 与干净全量签名构建，核对 ELF／bin／编译输入、官方验签、槽容量和 host/component 回归。构建不能读取已退役仓库、相邻 checkout 或隐式缓存补洞。每轮冻结完整 A/C、IDF／lwIP／MQTT／OTA、工具、客户端与生产信任；源码或签名改变完整 bin 后重新判断受影响资格。

### R5 C3 与 ESP32 实体容量和故障验收

每板独立核对身份、芯片、4 MiB、安全状态、新鲜恢复基线与唯一租约。在 Wi-Fi、严格 TLS MQTT、最忙业务和 OTA 同时工作时，完成正式公网升级、新 boot、原 ID 持久成功及再次启动查询；Mac 数据连接移除后也成立。

联合覆盖最大合法 MQTT 输入、满队列／在途／outbox、固件块与 ACK、重连、擦写、验签、NVS 提交和控制查询，分别满足 16,384／24,576／1,024 B 门，无非预期 OOM、overflow、失联或泄漏。核对全部能力域、最大后续申请与全任务实例，测量 OTA／配置／收据 Flash owner 的联合最坏延迟，保证长／短 owner 不互等。

两板分别实施意图写入、擦写中、验签后选槽前后、pending、自检确认、成功收据前后的真实断电／复位，证明正确镜像启动、坏镜像不获选、原结果可查或如实 unknown。常规冷启动不能替代故障阶段断电。实际 App／SDK 链路还须覆盖取消、失败后恢复、切换目标、多设备、身份不符及 App／Mac／USB 离线。

### R6 双板长稳与 Flash 使用目标

在同一最终候选完整通过 R5 后，每板完成 100 次网络／业务／升级生命周期和资源回收，再完成连续 72 小时原生业务＋MQTT＋周期公网分块 OTA。记录真实循环组成、断线恢复、操作终态、heap／连续块／栈趋势；不拼短测，不在中途更换候选或依赖继承资格。

Flash 设计使用目标仍为 5 年，按实际 OTA、收据、配置与失败恢复频率、Flash 型号及热点扇区核算。分块数不等于 NVS 擦写次数，任何持久重传进度机制都须单独核算。

### R7 正式交付与范围边界

交付物须与实际通过 R3／R5／R6 的完整签名 SHA、源码、组件锁和客户端一致。同步 Base、Server／Web 与 App 实际消费合同，保留失败、未验和退役历史；文档修订或仓库删除不替代构建、发布与运行验证。

ESP Tool App 正式发行仍按维护者 2026-10-19 决定暂缓；TestFlight／商店审核、正式安装及相关声明不作为当前完成门，也不标为通过。本地 App、固件和 Server／Web 工作可独立推进。完整 Rust SDK S1—S7（含独立 RFC2217 能力）范围保持，不随产品传输路线改变缩减；产品仅采用已冻结且实际验证的子集。
