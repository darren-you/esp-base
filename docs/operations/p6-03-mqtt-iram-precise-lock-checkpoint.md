同一签名 app、ECS2 与 Flash 种子还在 `mac-work-1:/private/tmp/esp-base-mqtt-frps-tls-four-full-messages-20260928/` 连续投递四条各 **4096 B** 的完整 QoS1 消息，Broker 记录四次投递和四次 PUBACK；FRP 单工作流双向各 300001 B 回显仍通过。工作完成后 MQTT `poll` 返回 `EMQTT_EVENT_ERROR`／`EMQTT_ERROR_QUEUE`（`kind=7 error=7`），按三槽上限关闭会话，不再交付已排队消息。普通内部 8BIT 堆历史最低 **52,224 B**，高于不变的 **49,152 B** 门 **3,072 B**，日志无堆申请失败。UART SHA-256 `902f23bddecacc4f96c0f02377bf98071078e1bd661292fe6d11713d0c251c60`，Broker 日志 SHA-256 `0a31127708ba90b9630e11d25cecf1a969e942cd88a9df92be8fbcc9803c97a4`；app、包区和 `base_store` 与种子逐字节相同，scratch 为全 `0xff`。[MQTT 源仓补充收据](https://github.com/esp-space/esp-mqtt/blob/05fb90a/docs/verification/mqtt-esp32-iram-placement.md)区分了队列溢出与四条业务交付。此次第四条是完整到达后触发溢出，不能替代三槽满而第四条稳定在途的容量观察；各轮低水差异不机械归因于单次分配。

这些试验仍是 OpenETH、仓外测试时钟及直连 FRP 探针：FRP 仅一条工作流，未测三条已排队时第四条仍在途、双活跃加预备流、OTA HTTPS 下载、正式 Base Wi-Fi／SNTP／HMAC owner、实体 Wi-Fi 与两块板的迁移恢复。模拟容量高于门槛不能验收 P6-03 五能力最坏组合，也不完成 P3-08 或 P7-02。诊断脚本先停止 OpenETH 才处理 MQTT 队列，后续 transport/TLS 错误与断线受关网顺序影响；这不证明正式停机路径或网络长稳。
