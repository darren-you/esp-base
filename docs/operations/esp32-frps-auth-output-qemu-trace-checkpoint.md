## 单独签名的现有超时字段输入

第二份在无 Git 的独立仓外副本编译，CMake 仅启用 FRP 精确锁已有的 `EFRP_LAB_TIMEOUT_TRACE=ON`，并让仓外 Base 探针多打印 `mux_timeout_source`、`stream_id`、`age_ms`、`pending_bytes`、`control_timeout_source`；探针源码 SHA-256 `bb36a989ef59ad052ff8e0501955481ab381a89a2a4ed01c7a31588ae31c267e`。FRP managed source 本身没有修改。状态结构和镜像时序因此改变，**本输入的堆数不能回填第一份或之前的容量基线**。新签名 app SHA-256 `5530d6353857f9a188522ee2ebcc397448f4ea57f2c1014363305bbf89fe08cc`，官方验签有效；大小 `0x10fff4` B，`0x120000` B 槽余 `0x1000c` B。新 ECS2 按新 app 摘要重建，种子 Flash SHA-256 `65ddb7effa33ae8c6606156d0c054c6f833db664be8a1cee00b70c60fe15a058`。

四次尝试均在 `AUTHENTICATING(3)` 约 5 秒后报 `-9`，TLS 清理快照 `verify=0`，没有进入 `REGISTERING`／`READY`。第二和第三次在退出认证时的 trace 分别为 `mux_source=1`（`EFRP_YAMUX_TIMEOUT_OUTPUT`）、`stream_id=0`、`age_ms=5012/5002`、`pending_bytes=12`；这 12 B 是 Yamux 输出队列中尚未确认交付的首个 SYN。第一和第四次 `mux_source=0`。由精确锁调用顺序可知 `efrp_session_step()` 在 `efrp_yamux_tick()` 前先调 `efrp_tls_step()`；TLS 已 OPEN 时其 5 秒 `EFRP_TIMEOUT` 只可能由尚有待写数据的 `t->used` 触发，而 `fail()` 会清零公开 TLS pending 状态。因此这两次是 **TLS 待写期限先于 Yamux 输出期限触发** 的源码推断，具体 TLS 待写字节数没有被保存，不能拿 Yamux 的 12 B 代替。其他两次可直接定位为 Yamux 输出无进展。服务端四次都记录 `isTLS: true`，随后 `AcceptStream() EOF`；仍没有接受首个控制 stream 或解析 Login 的证据。

新镜像第一次进入认证时 free／largest／启动低水为 `5,856／4,608／5,856 B`；整个启动的最低堆为 **904 B**。OpenETH 接收缓冲不足日志在本次强插桩输入中重复 29,088 行，日志与组件调度本身已明显改变运行条件，不能将此行数与前一次作同输入容量比较，也不能判定单一泄漏。额外探针任务最低未用栈 2,008 B，FRP worker 2,432 B。原始收据位于 `mac-work-1:/private/tmp/esp-frp-stack-timeout-trace-20260927/`：`qemu-uart.log` SHA-256 `e3764d263a7c2ce57b191073653918290bb12de134f769f4fb86d32aef629991`，`frps.log` `63acf27c3e5e21bce81a2b67e9ff3734861718a3c545dde251918356c18c01ca`，运行后 `qemu-flash.bin` `13c951d453d297d6b6ee77d91b3beead5b6fd95d3c7094dfa70f5cb977de9730`，验签输出 `3d4c27b901e82c0e6d5a10e896068f7d5937b51aa76ba48e80cbdbdbbfa3bff6`，构建日志 `7b5d9a68f30cd0e3997a47012e43d40313f364e5a32fd4a48c15908008fd0dce`，运行命令 `commands.json` `51dd0f83c3fcfd7a0d84134c0f796d3230f3055392d5a35d302c678a28e1a93f`。

## 结论边界

当前签名输入的最后可证网络进展是严格 TLS 握手；首个 Yamux 控制 SYN 未被 FRPS 接受，客户端输出停在 TLS／Yamux 的 5 秒待写期限。Hello／Login 的本地构造与写入 Yamux 缓冲不等于送达 socket，不能称服务端拒绝登录或未发送 LoginResp。极低堆余量与 OpenETH 接收缓冲不足同时存在，但现有日志没有具体 TLS 内部分配回溯或待写字节快照，不足以认定确定性 FRP 源码错误。保持 FRP／Base 正式源码、SDK 配置、栈门与内容上限不变；本检查点不构成正式 SNTP、FRP 登录／会话、P6-03 容量门或实板验收。
