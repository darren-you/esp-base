# P6-03：Base 静态 IRAM 产品落地与第三预备流检查点

2026-09-28。依据[仓外静态放置实验](p6-03-esp32-iram-bss-ota-experiment.md)，Base 的 `esp_base_protocol.c` 和 `mqtt_owner.c` 对五个现有静态对象使用固定 SDK `IRAM_BSS_ATTR`：协议上下文 **7,636 B**、MQTT 入站事件 **4,388 B**、请求 guard **2,568 B**、结果槽 **2,048 B**、FRP 状态重放槽 **768 B**，共 **17,408 B**。ESP32 已由构建门要求单核和 8BIT IRAM；C3 的 SDK 属性展开为空。对象大小、生命周期、读写、擦除与外部协议均未改，不引入分配失败或平行状态。host 假件仅把该 SDK 放置属性定义为空，以测试原有行为。受管 FRP／MQTT／OTA／Container 锁未变。

在仓外第三预备流签名 QEMU `mac-work-1:/private/tmp/esp-base-ota-iram-third-capacity-20260928/`，测试键 ECDSA v1 app SHA-256 `2f9522457fa0b688e458dad40d10e0f9cee476a08677739be337517d384867d7`，官方验签及 `0x120000` 槽尺寸检查通过；按新完整摘要生成 ECS2 sequence 6 和 4 MiB Flash 种子 SHA-256 `99d090ecc62017544fab73b3db044b48cf50e6cbb486be21d2bdd728cd2a227a`。真实签名 ABI 2 guest 到 `RUNNING`、Base 到 `READY`；严格 TLS FRPS `verify=0`、Pong 3，两条活跃工作流各方向 **300001 B** 回显。第三远端请求期间正式 FRP 状态为 `active=2 waiting=1 failed=0`，普通内部 8BIT 堆历史最低至该点 **54,072 B**，IRAM free／最大块 **7,204／2,176 B**。最终前两条 `completed=2`、总收发各 **600002 B**；第三条按工作流上限拒绝，`failed=1 last_error=EFRP_CAPACITY_EXCEEDED(-3)`，不是分配失败。该拒绝计入容量负例，不能报告三条业务工作流均成功。

同片公开 `eota_preflight`／`eota_prepare` 经严格 HTTPS 完整准备独立签名 Base app **1,114,100 B**，三条各 **4096 B** QoS1 MQTT 消息完整交付；全程普通内部 8BIT 堆历史最低 **52,664 B**，高于保持不变的 **49,152 B** 门 **3,512 B**。OTA 任务剩余栈高水 **6,624／12,288 B**；运行 app_0、产品包区、`base_store`、bootloader 和分区表读回不变，inactive app 与下载对象逐字节相同，scratch 恢复全 `0xff`。成功 UART SHA-256 `a82f71834559652f8b7178397c19f9beb0140619eb355c267f525d8e076f54c3`，运行后 Flash SHA-256 `93754e6974e5336a30c7395ca6b9f96fdd28ba04a13642f3d2606db2b2c38760`。诊断 app 含额外 `qemu_frps` 栈、OpenETH、测试时钟和仓外第三请求插桩，其容量不能直接替代无探针产品镜像。
