## 实际联合链

维护者授权丢弃数据后，整片擦除、写入 A 并完整读回。原公开 USB 工具提交 Wi-Fi／MQTT 配置版本 0→1→2；严格 TLS、可信时间、当前 boot 的非 retained reported、认证查询和 HMAC／QoS／远程配置写门负例通过。

公开安装来源包只发送一次，代表事件返回 guest result 19，经原连续 30000 ms 健康门后原安装 ID 持久成功，ECS2 1→6。公开 `ota.start` 只发送一次，模式为 `write`，从严格 HTTPS 分别下载签名 C 和不同摘要的新包；新 boot 的代表事件为原始字节 `01 02 03`，实际成功结果为 2。

原 OTA ID 沿既有 90 秒只读窗口取得 27 次 running、3 次有完整绑定结果的 `unknown/ota_result_uncertain`，最后 succeeded，未重发升级。原 30 秒健康门完成后，绑定为 C 与新包，实际版本为 v0-2-0、活动实例退出 trial，ECS2 6→11。

只发布一次 MQTT restart，取得 running 后，同设备进入第三个不同 boot，配置版本仍为 2。原 OTA ID 再次查询为 succeeded，确认产品重新装载，ECS2 保持 11；代表消息再次返回 2，随后计数查询仍为 2，支持 RAM 计数在新实例中重新开始。

在该确认实例上，公开事件发布器分别只发送下一帧，完成十二项业务检查：

| 顺序 | 行为 | 实际 guest result |
| --- | --- | --- |
| 1 | 首个定时窗口到期后查询 idle | 0 |
| 2 | 查询新实例计数 | 2 |
| 3 | 二进制消息体包含零字节，累计两个字节 | 4 |
| 4 | 暂停并保留计数 | 4 |
| 5 | 查询 paused | 2 |
| 6 | 暂停时拒绝消息 | -2，business_failed，发布器退出码 2 |
| 7 | 拒绝后计数不变 | 4 |
| 8 | 恢复 | 4 |
| 9 | 查询恢复后的 idle | 0 |
| 10 | 下一条二进制消息累计两个字节 | 6 |
| 11 | 第二个定时窗口到期后查询 idle | 0 |
| 12 | 最终计数保持 | 6 |

两次 idle 观察证明实际定时事件已完成，没有测量 100 ms 的物理调度上界。业务负结果由公开 reported／发布器按 business_failed 返回；它发生在已确认实例中，不能将其当作 runtime_failed 或安装失败。

公开卸载只发送一次，操作序号 2 的原 ID 持久成功，ECS2 11→12；十字段回读为空绑定和无活动实例，高水位 2、下一序号 3。完整 ECS2 序列为 1→6→11→11→12。HTTPS 六次完整 TLS 1.2 GET 包括宿主三份制品预检及设备各一次下载；固定 200、精确长度和摘要均通过。最后从 `0x20000`／`0x150000` 读取完整 A／C，逐字节核对原制品。
