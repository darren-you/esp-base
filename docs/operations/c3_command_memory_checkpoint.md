# C3 命令内存与控制栈检查点

2026-10-02，在 Base `9a739aabfae27a05a84ab16338a52e99f4267075` 上收敛命令分配和串口缓冲，并修正实板测得的控制栈不足。两目标软件验证和 C3 联合功能切片通过；普通内部堆及连续块仍未达到五能力资源门，首版未完成。

## 实际修改

`ebase_command_t` 保留身份和指纹字段，按选定命令类型独立申请载荷。只读 status／product.status 不申请载荷，结果查询只申请 37 字节 operation ID，config 和 OTA 仍保留原字段与限额。所有实际调用方采用同一新解析签名；分配沿用目标内存域，ESP32 控制载荷继续使用既有 8BIT IRAM 策略，C3 使用普通堆。解析失败或释放时清零已拥有的载荷；下一次解析先释放旧载荷。

已通过身份、revision 和写入准入的 config 直接交给候选试运行 owner，命令清除自己的载荷指针，结束试运行后由原 owner 清零释放。不再同时复制两份 7608 字节配置，也不改变持久化、连接证明或失败恢复行为。OTA 请求仍在准入后复制到既有异步 owner。

串口行读取结构改为指针、长度和容量，缓冲从 64 字节按实际输入增长，最大有效行仍为 9216 字节。扩容先复制已用字节，再清零并释放旧区；正常完成、NUL、超限、申请失败和两秒半包超时均清零回收。拒绝后排空到 LF，下一条完整命令才能重新解析；回调只在返回前借用行字节。

官方 C3 编译器的实际对象尺寸如下，不能使用 64 位宿主尺寸替代目标测量。

| 对象 | 修改前／B | 修改后／B |
| --- | ---: | ---: |
| 命令结构 | 7768 | 168 |
| 行读取结构 | 9228 | 16 |
| config 载荷 | 7608 | 7608，按需且单一 owner |
| OTA 载荷 | 1696 | 1696，按需 |

第一轮实板的控制任务仍为 6144 字节，联合下载最低栈余量只有 352 字节，未通过 1 KiB 门。第二轮将两个目标的控制任务统一为 8192 字节，保持主任务 6144 字节、FRP／OTA 任务及各组件既有限额。TLS IN 16384／OUT 4096、FRP 64 KiB 记录、guest 64 KiB 线性内存、MQTT 队列与正式分区均未降低。

固定 ESP-IDF `578cf89c343e388db43ba1f4ddcd602fedcb763c`／lwIP `2758df4cd3666b3b2a5b53830148379326425c0d` 下，C3／ESP32 普通 SDK 构建、测试键签名、官方验签及完整 host 回归通过。签名 app 分别为 1183744／1114100 字节；七份修改源码／测试与 SDK 冻结输入逐字节一致，四份依赖锁保持。

ASan／UBSan 测试覆盖命令复用、载荷申请失败后恢复、敏感配置清零、配置所有权移交与试运行存活期、两秒超时边界、九个行缓冲扩容失败点、9216／9217 字节边界、NUL 排空和下一命令恢复。短 status 行缓冲峰值为 192 字节；既有严格 JSON 和 10000 次确定性畸形输入回归继续通过。

C3 第二轮使用原始应用入口、正式布局及精确依赖，私有配置仅实验 CA、timer 授权／一个定时器和目标版本 `0.2.0-c3-lab-memory-stack-c`。另加每秒只读实验 trace，记录普通内部 8BIT heap、连续块和当前控制任务栈；trace 不进入生产源码，未注入调用方或健康事实。

公开产品安装、一次 WRITE 联合 OTA、一次 MQTT restart、十二项消息计数业务和公开卸载通过。141 份来源下载采样均保持 MQTT／FRP ready；目标与第三 boot 经 Tool 既有控制库核验 FRP 认证状态，设备身份、revision 3、确认产品及原 OTA 成功结果保持。写命令没有重发。
